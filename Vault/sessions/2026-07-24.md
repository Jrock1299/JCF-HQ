#### Jase's one-time Google Cloud Console runbook
1. **console.cloud.google.com** → pick/create a project (e.g. "JCF HQ").
2. **APIs & Services → Library** → search "Google Drive API" → **Enable**.
3. **APIs & Services → OAuth consent screen:** User type **External** → fill app
   name / your email → **Save**. Add your Gmail under **Test users**. Then
   **Publish app → In production** (Testing mode expires refresh tokens after 7
   days; Production makes them durable). `drive.file` is non-restricted, so no
   Google verification is required.
4. **APIs & Services → Credentials → Create Credentials → OAuth client ID →
   Application type: Desktop app** → Create → **Download JSON**.
5. Put that JSON on the VPS at
   `/root/.openclaw/credentials/gdrive/client_secret.json`.
6. In the session, run:
   `! /root/.openclaw/venv/bin/python3 /root/.openclaw/scripts/gdrive_auth.py`
   → open the printed URL, approve, paste the `code=` from the (failing)
   localhost redirect. This writes `token.json`.
7. Verify: `! /root/.openclaw/venv/bin/python3 /root/.openclaw/scripts/gdrive_sync.py`
   → prints the Drive folder link.
8. Activate the cron: remove `#HOLD` from the `run_gdrive_sync.sh` line.

### The one gotcha (worth remembering)
The task spec said to use `--model openai/gpt-5.5-codex`. That **fails** through
`openclaw agent`: `FailoverError: Unknown model … bound to the "codex" agent
runtime … served by an agent runtime, not models.providers`. The `-codex`
suffixed ids can't be passed as `--model` overrides. The working string is plain
**`openai/gpt-5.5`** (which is exactly what Jase reported testing successfully).
This is also why Lucy's `PRIMARY_MODEL = openai/gpt-5.3-codex` silently falls
back to `openai/gpt-5.5`.
