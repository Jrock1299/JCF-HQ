## 2. Jerry's P&L pipeline — three defects, not one

The reported symptom was "all 90 closed trades record `pnl: 0.0`". Investigation
found that was the visible third of a fully broken pipeline. See [[jerry]] for
the detail; summary:

1. **The close-path race.** `_mark_closed` computed P&L only inside
   `if symbol not in positions:` — evaluated microseconds after submitting a
   market close order. Alpaca still lists the position until that order fills,
   so the branch never executed. 90/90 closes affected.
2. **Server-side exits never recorded.** Bracket SL/TP orders fill at the
   broker and never call `close_position()`, so those trades stayed `open`
   locally forever. Local file said 39 open; broker had 8.
3. **Entry price was never the fill.** `buy_stock` recorded the pre-trade
   snapshot as cost basis — wrong on **119 of 126** records, understating the
   book by ~$5.1k. This one matters most: even with defects 1 and 2 fixed,
   every P&L number would still have been wrong.

**Fix.** Both entry and exit prices now come from the broker's own fill record
via `_resolve_order_fill()` (`filled_avg_price`, already VWAP across partial
fills). Added `reconcile_closed_positions()`, called at the top of every
trading tick, to close out broker-side exits. Where a fill cannot be
established the trade records `pnl=None` + `pnl_status=UNVERIFIED_*` — never a
fabricated `$0`, which would drag win rate and expectancy toward zero. This
applies Rule #9 at the *write* side, not only at the grading side.

**Verification.** A real paper round-trip on Alpaca (buy 20 F, close, inspect):
entry $14.43 from `order_fill`, exit $14.42 from `close_order_fill`,
pnl −$0.20, `pnl_status VERIFIED`, arithmetic matching. Run against a scratch
history file so production data stayed clean.

**Backfill.** Rebuilt the history from Alpaca's FILL activity feed — entries
corrected exactly by order id, exits matched lot-level FIFO. Reconciles to
broker cash flows within **$0.04** across the book. A first attempt using
order-level FIFO gave +$141 against a broker figure of −$8,228; the gap was
the uncorrected entry prices plus a missing options multiplier.

**Options are ×100.** Activity `price` is the per-share premium; cash flow is
`qty × price × 100`. Confirmed two ways: Alpaca's own `cost_basis` (5 × $0.72 ×
100 = $360), and implied starting equity, which resolves to $99,996 ≈ the
documented $100,000 start only with the multiplier applied.

**Result.** [[victoria]]'s validator grades Jerry for the first time:

ruin 0.0%. A real verdict on real data, replacing the NO_DATA it correctly
